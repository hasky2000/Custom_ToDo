# Custom ToDo

学生の授業内で作成するTODOアプリです。PHP・PostgreSQL・Docker Composeを使用します。

## 今回追加した機能

- 新規登録ではパスワードを2回入力します。不一致の場合は画面とAPIの両方で登録を拒否します。
- ホームの右側にあるハンドルをドラッグしてタスクを並べ替えます。タッチ操作にも対応します。キーボードではハンドルにフォーカスして↑↓キーを使います。順番はユーザーごとにDBに保存します。新規・復元したタスクは末尾に追加します。
- フッターはTODOとマイページの2項目です。マイページの「アーカイブを見る」から専用画面を開きます。完了日ごとの表示と、タイトル・内容のキーワードと完了日による絞り込みができます。URLの `#archive` からの表示やブラウザの戻る操作にも対応します。
- アーカイブの「TODOに戻す」で未完了・進捗0%に戻します。タイトル・内容・予定日時は保持します。
- ログイン時は `password_verify` で入力パスワードを保存済みハッシュと照合し、一致した場合だけログインします。
- マイページの「デバッグページを見る」で、自分のアカウント情報・パスワードハッシュ・ログイン照合記録・セッション設定・タスク件数と保存データ・実行環境を確認できます。「情報を更新」で再取得できます。
- パスワードの平文は保存していません。デバッグ画面のパスワード情報はDBに保存されたハッシュです。

## 以前の認証不具合について

以前は `app/db.php` の `$password` がAPIの入力パスワードを上書きしていました。
その結果、登録時にDB接続用パスワードのハッシュが保存され、ログイン時の入力パスワードが正しく照合されていませんでした。
DB接続用の変数名を分離し、入力パスワードを保存・照合するよう修正しました。
この不具合で作成されたアカウントには元の入力パスワードが保存されていないため、パスワードの再設定が必要です。
デバッグ画面ではDB接続用パスワードと一致するハッシュを非表示にし、再設定が必要な可能性があることを表示します。

## 既存のDBを更新する

新規のDBには `database/init` のSQLが自動で適用されます。
既存のDBでは初期化SQLが再実行されないため、次のコマンドで今回の変更を適用します。
既存のタスクと完了日時を保持し、従来の表示順で並び順を初期化します。

```sh
docker compose exec -T db sh -c 'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -v ON_ERROR_STOP=1 --single-transaction' < database/init/005_add_task_order_and_completed_at.sql
```

## 動作検証

`db` と `php` の開発コンテナが起動している状態で実行します。
検証用DBを作成してAPIをテストし、終了時に検証用DBを削除します。
通常の開発DBは使用しません。

```sh
bash tests/run.sh
```
